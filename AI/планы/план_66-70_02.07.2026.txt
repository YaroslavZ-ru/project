        async def save_concept_endpoint(request: Request, body: SaveConceptRequest):
            _verify_api_key(request)
            if _cfg is None or _kb is None:
                raise HTTPException(503, detail="Сервис не готов")

            try:
                parameters = []
                for p in body.parameters:
                    param_dict = {
                        "name": p.name,
                        "label_ru": p.label_ru,
                        "type": p.type,
                        "description": p.description,
                        "unit": p.unit,
                        "enum_values": p.enum_values,
                        "confidence": p.confidence,
                    }
                    parameters.append(param_dict)

                        "relation_type": r.relation_type,
                        "confidence": r.confidence,

                    _kb.save_concept,
                    body.term,
                    body.domain,
                    parameters,
                    relations if relations else None,
                )
                return SaveConceptResponse(concept_id=concept_id)
            except Exception as exc:
                logger.exception("Ошибка save_concept: %s", exc)
                raise HTTPException(500, detail=f"Ошибка сохранения: {exc}") from exc

КОНТЕКСТ И ЗАДАЧА
-----------------

описание (раздел 20) описывает расширенный режим: после основного поиска

ИЗМЕНЕНИЕ 68: Коррекция результатов по обратной связи
================================================================================

КОНТЕКСТ И ЗАДАЧА
-----------------
Пользователи могут оценивать результаты (rating 1-5). Финальное описание
(раздел 24.3) описывает механизм коррекции: средний рейтинг понятия
влияет на confidence при поиске. Понятия с высоким рейтингом получают
boost, с низким — penalty. Это статистическая обратная связь без
дообучения модели.

ПОЧЕМУ ЭТО ВАЖНО
----------------
  - улучшает качество поиска на основе пользовательского фидбэка;
  - автоматически повышает релевантные понятия;
  - не требует ручной настройки весов.

ДЕТАЛИ РЕАЛИЗАЦИИ
-------------------

        3. Если таблица feedback не существует -> {"avg_rating": None, "votes": 0}.

  src/aggregation.py
    - Добавить функцию apply_feedback_correction(
          candidates: list[dict],
          kb: KnowledgeBase,
          weight: float,
          min_votes: int,
      ) -> list[dict]:
        1. Для каждого кандидата:
            concept_id = c.get("concept_id")
            if not concept_id: continue
            stats = kb.get_feedback_stats(concept_id)
            if stats["votes"] < min_votes: continue
            avg = stats["avg_rating"]
            if avg is None: continue
            multiplier = 1.0 + (avg - 3.0) * weight
            multiplier = max(0.5, min(multiplier, 1.5))  # Ограничить [0.5, 1.5]
            c["similarity"] = min(c["similarity"] * multiplier, 1.0)
        2. Пересортировать candidates по similarity.
        3. Вернуть обновлённый список.

ИЗМЕНЕНИЕ 70: Полный набор метрик и EMA-усреднение
================================================================================

КОНТЕКСТ И ЗАДАЧА
-----------------
Текущий MetricsCollector считает requests_total, ok/error/fallback и cache.
Финальное описание (раздел 26.1) требует расширенный набор: requests_ambiguous,
generative_calls, generative_timeouts, fallback_activations, а также
EMA-усреднение avg_pipeline_ms (skeweda average с alpha=0.1).

ПОЧЕМУ ЭТО ВАЖНО
----------------
  -Allows детальный анализ поведения системы в продакшене;
  - помогает выявить узкие места (много таймаутов генерации?);
  - EMA даёт более стабильную оценку среднего времени.

-------------------

        Добавить счётчики:

            _counts["generative_timeouts"] = 0
            _counts["fallback_activations"] = 0
            _counts["cache_hits_search"] = 0
            _counts["cache_misses_search"] = 0

            )
