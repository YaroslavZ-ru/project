ЧТО НУЖНО СДЕЛАТЬ
-----------------
Добавить time-based expiry (TTL) в кэш результатов поиска внутри
KnowledgeBase. Сейчас кэш живёт бесконечно до ручной очистки.

ПОЧЕМУ ЭТО НУЖНО
----------------
Финальное описание (раздел 10.7) указывает:
  "TTL: Config.search_cache_ttl_seconds (по умолчанию 300с, 0 = без TTL)"
Без TTL устаревшие результаты могут возвращаться бесконечно.

ДЕТАЛИ РЕАЛИЗАЦИИ
-------------------
src/config.py:
  Уже есть search_cache_ttl_seconds: int = 300.
  Убедиться что поле присутствует и валидируется (int >= 0).

src/knowledge_base.py — кэш поиска:
  Текущая реализация: OrderedDict с LRU-эвикцией.
  Добавить TTL: хранить (result, timestamp) вместо result.

  ИЛЛЮСТРАЦИЯ:
    from collections import OrderedDict
    import time

    class SearchCache:
        def __init__(self, maxsize: int, ttl_seconds: int):
            self._cache: OrderedDict = OrderedDict()
            self._maxsize = maxsize
            self._ttl = ttl_seconds
            self._lock = threading.Lock()

        def get(self, key: tuple) -> list | None:
            with self._lock:
                if key not in self._cache:
                    return None
                result, ts = self._cache[key]
                if self._ttl > 0 and (time.monotonic() - ts) > self._ttl:
                    del self._cache[key]
                    return None
                self._cache.move_to_end(key)
                return result

        def put(self, key: tuple, result: list) -> None:
            with self._lock:
                if len(self._cache) >= self._maxsize:
                    self._cache.popitem(last=False)
                self._cache[key] = (result, time.monotonic())

        def clear(self) -> None:
            with self._lock:
                self._cache.clear()

  Если search_cache_ttl_seconds == 0 -> TTL не применяется (кэш живёт
  до эвикции по размеру или ручной очистки).

  Инвалидация: при save_concept или update_all_embeddings -> self._search_cache.clear().

ИЗМЕНЕНИЕ 78: Коллизия UUID сессий
================================================================================

ЧТО НУЖНО СДЕЛАТЬ
-----------------
Добавить обработку коллизии UUID при создании сессии. Финальное описание
(раздел 32.9) описывает: INSERT OR IGNORE + повторная генерация UUID
максимум 3 раза.

ПОЧЕМУ ЭТО НУЖНО
----------------
UUID4 имеет крошечную вероятность коллизии, но при большом объёме сессий
она не нулевая. Без обработки INSERT может молча проигнорировать запись.

ДЕТАЛИ РЕАЛИЗАЦИИ
-------------------
src/sessions.py — метод create_session():
  ИЛЛЮСТРАЦИЯ:
    def create_session(self, term: str, hints: list[str]) -> str:
        max_attempts = 3
        for attempt in range(max_attempts):
            session_id = str(uuid.uuid4())
            try:
                if self._storage == "sqlite":
                    self._conn.execute(
                        "INSERT INTO sessions (id, term, hints, ...) "
                        "VALUES (?, ?, ?, ...)",
                        (session_id, term, json.dumps(hints), ...)
                    )
                    self._conn.commit()
                else:
                    self._data[session_id] = {...}
                return session_id
            except sqlite3.IntegrityError:
                if attempt < max_attempts - 1:
                    logger.warning(
                        "UUID коллизия, попытка %d/%d",
                        attempt + 1, max_attempts
                    )
                    continue
                raise RuntimeError(
                    f"Не удалось создать сессию после {max_attempts} попыток"
                )

  Для in-memory хранилища: коллизия невозможна (dict не допускает
  дублирующих ключей), поэтому retry не нужен.

ИЗМЕНЕНИЕ 79: FAISS: нехватка данных для train
================================================================================

ЧТО НУЖНО СДЕЛАТЬ
-----------------
Добавить автоматическую настройку nlist при недостаточном количестве
данных для обучения IVF+PQ индекса. Финальное описание (раздел 32.10).

ПОЧЕМУ ЭТО НУЖНО
----------------
IndexIVFPQ требует минимум nlist * 39 векторов для train(). Если данных
меньше -> faiss.train() падает с ошибкой. Автоматическая настройка
предотвращает сбой.

ДЕТАЛИ РЕАЛИЗАЦИИ
-------------------
scripts/build_faiss.py — алгоритм построения индекса:
  ИЛЛЮСТРАЦИЯ:
    N = len(embeddings_matrix)

    if N < 256:
        # Мало данных — точный поиск, скорость несущественна
        index = faiss.IndexFlatIP(300)
    else:
        nlist = min(4096, max(256, int(N ** 0.5)))
        min_train = nlist * 39
        if N < min_train:
            nlist = max(1, N // 39)
        quantizer = faiss.IndexFlatIP(300)
        index = faiss.IndexIVFPQ(quantizer, 300, nlist, 64, 8)
        index.train(embeddings_matrix)
        index.add(embeddings_matrix)
        index.nprobe = 32

  ВАЖНО: nlist не может быть 0. Если N < 39 -> fallback на IndexFlatIP.

src/knowledge_base.py — _build_faiss_index():

M-1. Feedback confidence multiplier:
  При коррекции по feedback similarity умножается на multiplier.
  Ограничить результат: min(similarity * multiplier, 1.0).
  Файл: src/aggregation.py (если есть apply_feedback_correction).

M-6. lemmatize_word: parse[0] вместо max():
  pymorphy3 возвращает список отсортированным по убыванию score.
  parse[0] — уже лучший разбор, max() избыточен.
  Файл: src/lemmatizer.py, метод lemmatize_word().
  ИЛЛЮСТРАЦИЯ:

    СТАЛО: best = parse[0]

M-7. Хэш для param name:
  Использовать hashlib.md5 вместо hash() для стабильности.
  hash() нестабилен между запусками из-за PYTHONHASHSEED.
  Файл: src/generative.py.
  ИЛЛЮСТРАЦИЯ:
    БЫЛО:  name = "param_" + str(abs(hash(label_ru)))[:8]
    СТАЛО:  name = "param_" + hashlib.md5(label_ru.encode()).hexdigest()[:8]

M-10. SynonymDict weight validation:

  Файл: src/synonyms.py, метод get_synonyms() или при загрузке.

M-15. Декоратор timed: try/finally:
  ИЛЛЮСТРАЦИЯ:
    def timed(func):
        def wrapper(*args, **kwargs):
            start = time.perf_counter()
            try:
                return func(*args, **kwargs)
            finally:
                elapsed = (time.perf_counter() - start) * 1000
                logging.getLogger(func.__module__).debug(
                    "%s завершена за %.2f мс", func.__name__, elapsed
                )
        return wrapper

  Файл: src/utils.py.
