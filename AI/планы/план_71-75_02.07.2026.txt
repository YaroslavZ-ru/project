ИЗМЕНЕНИЕ 71: Автоматическая пересборка FAISS-индекса
================================================================================

КОНТЕКСТ И ЗАДАЧА
-----------------
Сейчас FAISS-индекс строится вручную через scripts/build_faiss.py. При
добавлении новых понятий через save_concept индекс устаревает. Финальное
описание (раздел 21.3) описывает автоматическую пересборку в фоновом
потоке при превышении порога.

ПОЧЕМУ ЭТО ВАЖНО
----------------
  - индекс всегда актуален без ручного вмешательства;
  - не блокирует основной поток обработки запросов;
  - при большом объёме данных индекс автоматически переключается
    с IndexFlatIP на IVF+PQ.

ДЕТАЛИ РЕАЛИЗАЦИИ
-------------------

  src/knowledge_base.py
    - Добавить атрибуты:
        _faiss_rebuild_lock: threading.Lock = threading.Lock()
        _faiss_rebuild_pending: bool = False

    - Добавить метод _maybe_rebuild_faiss():
        1. Если use_faiss=False -> выйти.
        2. Подсчитать количество concepts: SELECT COUNT(*) FROM concepts.
        3. Если count < faiss_threshold -> выйти.
        4. Если _faiss_rebuild_pending -> выйти (уже запланирована).
        5. Установить _faiss_rebuild_pending = True.
        6. Запустить в daemon-потоке: threading.Thread(target=_rebuild_faiss_async, daemon=True).start()

    - Добавить метод _rebuild_faiss_async():
        1. Попытаться захватить _faiss_rebuild_lock (non-blocking).
           Если не удалось ->另一位 поток уже пересобирает, выйти.
        2. with _faiss_rebuild_lock:
            _faiss_rebuild_pending = False
            try:
                # Загрузить все эмбеддинги
                concepts = self.get_all_concepts(use_cache=False)
                valid = [c for c in concepts if c.get("embedding") is not None and np.any(c["embedding"] != 0)]
                if len(valid) < 256:
                    logger.info("FAISS rebuild: мало данных (%d), пропуск", len(valid))
                    return
                embeddings = np.vstack([c["embedding"] for c in valid]).astype(np.float32)
                ids = [c["id"] for c in valid]
                # Построить индекс (тот же алгоритм что в build_faiss.py)
                new_index = self._build_faiss_index(embeddings)
                # Заменить под локом
                with self._faiss_lock:
                    self._faiss_index = new_index
                    self._faiss_ids = ids
                logger.info("FAISS rebuild завершён: %d векторов", len(valid))
            except Exception as exc:
                logger.error("Ошибка FAISS rebuild: %s", exc)

    - Добавить метод _build_faiss_index(embeddings: np.ndarray):
        if not _FAISS_AVAILABLE:
            return None
        N = len(embeddings)
        if N < 100_000:
            import faiss
            faiss.normalize_L2(embeddings)
            index = faiss.IndexFlatIP(300)
            index.add(embeddings)
        else:
            import faiss
            nlist = min(4096, max(256, int(N ** 0.5)))
            if N < nlist * 39:
                nlist = max(1, N // 39)
            quantizer = faiss.IndexFlatIP(300)
            index = faiss.IndexIVFPQ(quantizer, 300, nlist, 64, 8)
            index.train(embeddings)
            index.add(embeddings)
            index.nprobe = 32
        return index

    - В save_concept: после сохранения вызвать _maybe_rebuild_faiss().
    - В update_all_embeddings: после обновления вызвать _maybe_rebuild_faiss().

  tests/test_knowledge_base.py

ИЗМЕНЕНИЕ 75: Оптимизация матрицы эмбеддингов
================================================================================

КОНТЕКСТ И ЗАДАЧА
-----------------
Матрица эмбеддингов (_embeddings_matrix) используется для линейного поиска
numpy. Сейчас она строится при первом вызове search_similar (ленивая
инициализация). Финальное описание (раздел 22) описывает полный жизненный
цикл: ленивую инициализацию, инвалидацию при изменении данных, thread-safe
доступ через _matrix_lock.

ПОЧЕМУ ЭТО ВАЖНО
----------------
  - ускоряет повторные поисковые запросы (нет重建ования матрицы);
  - потокобезопасность при параллельных запросах;
  - корректная инвалидация при обновлении данных.

ДЕТАЛИ РЕАЛИЗАЦИИ
-------------------

  src/knowledge_base.py
    - Добавить атрибуты:
        _embeddings_matrix: np.ndarray | None = None
        _matrix_concept_ids: list[str] | None = None
        _matrix_lock: threading.RLock = threading.RLock()

    - Добавить метод _ensure_embeddings_matrix():
        with self._matrix_lock:
            if self._embeddings_matrix is not None:
                return
            concepts = self.get_all_concepts(use_cache=True)
            valid = [c for c in concepts
                     if c.get("embedding") is not None
                     and np.any(c["embedding"] != 0)]
            if not valid:
                self._embeddings_matrix = np.zeros((0, 300), dtype=np.float32)
                self._matrix_concept_ids = []
                return
            self._embeddings_matrix = np.vstack(
                [c["embedding"] for c in valid]
            ).astype(np.float32)
            self._matrix_concept_ids = [c["id"] for c in valid]
            logger.info(
                "Матрица эмбеддингов построена: %d x 300",
                len(valid)
            )

    - Добавить метод _invalidate_embeddings_matrix():
        with self._matrix_lock:
            self._embeddings_matrix = None
            self._matrix_concept_ids = None
            logger.debug("Матрица эмбеддингов инвалидирована")

    - В search_similar: использовать _ensure_embeddings_matrix()
      вместо ручного построения матрицы.

    - В save_concept: после сохранения вызвать _invalidate_embeddings_matrix().
    - В update_all_embeddings: после обновления вызвать _invalidate_embeddings_matrix().

    - Добавить в search_similar thread-safe доступ:
        with self._matrix_lock:
